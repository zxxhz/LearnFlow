## 三、P0 清单（致命故障/安全漏洞）

### P0-1 `backend/app/services/relay/sync.py:317-319`｜pull 墓碑段直接删除题库行触发外键崩溃，多端同步被永久阻断

- **位置**：`backend/app/services/relay/sync.py:317-319`（关联 `server/db.py:472-480`、`backend/app/models/bank.py:33/58`、`backend/app/core/db.py:29`）
- **问题**：pull 墓碑段对 QuestionBank 直接 DELETE 不先清理子行，而外键无 ON DELETE CASCADE 且连接开启 `PRAGMA foreign_keys=ON`，删除仍有子题/作答的题库必撞 IntegrityError，整个 pull 失败。
- **证据摘要**（verified + 主会话复核）：该 DELETE 为 `delete(QuestionBank).where(QuestionBank.id.in_(chunk))` 且无子行清理；服务端墓碑只增不删（`server/db.py:476-480` 为 INSERT ON CONFLICT DO NOTHING）；该段代码注释自述为 v0.5.8 针对上一轮 P1（pull 复活死循环）的修复，实际引入了本条致命缺陷。
- **触发路径**：任一设备删除仍有子题/作答的题库 → 墓碑推送云端 → 任何仍持有这些子行的设备 pull → 墓碑段 DELETE 触发 IntegrityError → pull 整体失败；因服务端墓碑永不清理，之后每次 pull 都在同一位置复现，多端同步被永久阻断（课程/文档/导图等所有域一并失效），只能手工清库解除。
- **修复方向**：墓碑段先删子行（或为外键补 ON DELETE CASCADE），服务端墓碑引入确认/TTL 清理，并补含子行题库删除后双端 pull 的回归测试。

## 四、P1 清单（严重缺陷/数据丢失）

### P1-1 `server/main.py:356`｜未 import json：AI 深度解析必挂 500，云端备份双写全部静默失效

- **问题**：server/main.py 未 import json（复核确认），错题 AI 深度解析端点每次调用 NameError→500 必挂；229/254/326/419/442/575 行的 json.dumps 位于 try/except 内被吞，六处端点的「隧道转发本地」分支永远走不到。
- **触发路径**：服务端带病启动 → AI 深度解析每次 500；submit_bank_attempt、draw_bank_round、update_bank_question、update_bank、study/profile 更新与 polish-prompt 宣称的「本地成功后云端备份」双写全部静默失效。
- **修复方向**：补 `import json`，被吞异常改为记日志或显式失败，并为六处转发分支补回归用例。

### P1-2 `server/auth.py:219`｜token 走 query 参数且访问日志不脱敏，共享令牌泄漏即交出云端全部读写权

- **问题**：鉴权表单 JS `searchParams.set('token')` 整页跳转；`server/auth.py:249-259` 与 `server/tunnel.py:391` 均接受 query token；uvicorn 默认 access log 记录完整 path+query，无本地端 `backend/app/main.py:190-206` 的 _TokenLogFilter 同款脱敏。
- **触发路径**：完整共享令牌进入浏览器历史与服务端/反代/Docker 访问日志 → 任何能读到日志的一方获得云端全部读写权。
- **修复方向**：移除 query token 接收与表单跳转中的 token 传递（改表单 POST 或一次性换发），服务端日志接入同款过滤器。

### P1-3 `backend/app/api/courses.py:222-245`｜课程/文档/思维导图删除不记同步墓碑，删除在下次 pull 被原样复活

- **问题**：全库仅 bank/bank_question 两处记墓碑；服务端对这些表只 upsert 不删、pull 按缺即建。
- **触发路径**：删除课程/文档/导图 → 下一次 pull 云端仍持有该行 → 原样复活；单机+云端场景同样必然复现。
- **修复方向**：删除路径统一补记 SyncTombstone 并随 push 上报，服务端对带墓碑对象不再按缺即建。

### P1-4 `backend/app/services/relay/sync.py:499-502`｜pull 合并把云端空 updated_at 当最新，存量行本地编辑被回退后固化丢失

- **问题**：云端空 updated_at（""）走「云端胜」分支直接覆盖本地，与迁移注释「'' 视为最旧」语义相反；作答撤回（revoke_attempt 置 T1）同型被回退成未撤回。
- **触发路径**：0.5.8 前存量行做本地编辑 → 双向同步（pull 固定先行）→ 云端旧快照覆盖本地 → push 固化，编辑永久丢失。
- **修复方向**：合并比较中空 updated_at 一律视为最旧，并为存量行补一次性 updated_at 回填迁移。

### P1-5 `backend/app/services/relay/sync.py:618-626`｜导图/课程/文档 pull 合并无新者胜护栏，本地编辑被旧版本无条件覆盖

- **问题**：三个域 pull 合并无任何时间戳比较、无条件整字段覆盖，与题库域已实现的字段级新者胜口径不一致。
- **触发路径**：本地编辑导图/课程/文档 → 触发同步（pull 先行）→ 云端旧版本覆盖本地新树 → push 把旧版本固化。
- **修复方向**：三域复用题库域的字段级新者胜合并实现，并补「编辑后同步不回退」回归测试。
