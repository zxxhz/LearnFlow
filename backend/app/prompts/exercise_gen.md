## 关卡设计要求
共设计 [[COUNT]] 个关卡（第 1 关 → 第 [[COUNT]] 关），全部为代码关（kind = "code"），规则：
- 语言固定为 `[[LANGUAGE]]`，`language` 字段必须填 `[[LANGUAGE]]`
- 难度递进：第 1 关只考本知识点最核心的一小步；中间关逐步组合变式；最后一关综合运用（仍不得超纲，不引入教材原文之外的新概念）
- 每关单文件、可独立运行；只用该语言的标准库与内建功能，禁止任何第三方依赖
- **禁止从标准输入读取**（不允许 `input()` / `std::cin >>` / `scanf` 等等待用户输入的语句）
- 禁止使用随机数、当前时间/日期、文件读写、网络——运行输出必须**完全确定**，任何人任何时刻运行结果都一样
- 各关考察点不重复：同一主题允许换场景，但不要考同一个东西两遍
- `title` 形如「第 N 关：xxx」（15 字内）

### hints（渐进提示，必填，2~3 条，按展开顺序）
学习者会逐条展开提示，提示必须真的有用且不剧透过头：
- 第 1 条：指路——该用教材原文里的哪个概念/哪段知识，一句话点破思考方向
- 第 2 条：关键 API / 语法要点 / 算法思路或易错点
- 第 3 条（可选）：接近伪代码的步骤拆解，但不得给出可直接粘贴的完整代码

### task（关卡任务，必填）
- 用中文写清楚：写一个程序做什么、**程序必须输出什么样的内容**（明确到输出的格式与含义）
- 可用 markdown；不要把答案或参考代码写进任务里

### expected_output（目标输出，必填）
- 必须是参考实现运行后的**完整标准输出**，逐字符精确（包括空格、换行、标点），前后不要添加"输出为："之类的提示语

### reference_code（参考实现，必填）
- 能通过本关的完整可运行代码，风格简洁，只用到本知识点与此前已学内容；学习者通关后才会看到它

## 输出格式（严格遵守）
只输出一个 JSON 对象，不要包代码块标记，不要输出任何解释文字。字符串内的换行必须转义为 \n。exercises 数组顺序即关卡顺序，必须给满 [[COUNT]] 关：
