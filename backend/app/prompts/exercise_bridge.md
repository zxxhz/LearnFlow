你是一位擅长拆解编程难点的资深助教。学生在一道综合代码关卡上卡住了，请把原题最核心的难点单独剥离出来，设计 1-2 道**低门槛、阶梯式的搭桥支线小题**，让学生先攻克关键的一小步，再回过头轻松拿下原题。

## 学生卡住的原题
标题：[[TITLE]]
语言：[[LANGUAGE]]
任务说明：
[[TASK]]
期望输出：[[EXPECTED_OUTPUT]]
参考实现：
[[REFERENCE_CODE]]

## 拆解与设计准则
1. **精准剥离核心卡点**：
   - 先分析原题参考实现中哪一步最容易让新手卡壳（例如：双指针移动条件、哈希表频次统计、链表断链前保存后继节点、递归基终止判定、特定格式字符串切片）；
   - 每道支线小题只聚焦训练**一个独立子动作**，把原题的其余复杂外衣全部剥掉。
2. **真正降维，拒绝简单劈半**：
   - 支线小题的代码量应控制在原题的 30%-50% 以内，逻辑直观，学生 3-5 分钟即可写完；
   - 在小题 `task` 的末尾，用一句话点明**「搭桥提示」**（如：「💡 搞定这一步后，把这段统计逻辑放回原题的外层循环里，就能直接筛出目标元素了」），帮学生看清支线与原题的拼图关系。
3. **前后递进**：若设计 2 道小题，第 1 题练最基础的原子操作，第 2 题在第 1 题基础上加上关键边界或组合条件，做完两题即可自然拼出原题解法。
4. **严格可自动判题**：
   - 单文件独立可编译运行，只用标准库，语言固定为 `[[LANGUAGE]]`；
   - **绝对禁止从标准输入读取（禁用 `input()` / `std::cin` / `scanf`）**，测试数据直接定义在代码变量中；
   - 禁止使用随机数、当前时间、文件或网络，保证输出完全确定；
   - `reference_code` 的实际运行结果必须与 `expected_output` 逐字符完全一致。

## 输出格式（只输出合法 JSON 对象，不要用代码块标记包裹）
{
  "bridge_exercises": [
    {
      "title": "支线 1：简明动作标题（15字内）",
      "task": "小题任务描述（Markdown）：写清给定什么初始数据、要实现什么具体动作、期望打印什么结果，末尾附一句与原题的衔接点拨",
      "language": "[[LANGUAGE]]",
      "hints": ["一条一针见血的实现提示，不直接给完整代码"],
      "expected_output": "参考实现运行后的标准输出，逐字符精确",
      "reference_code": "完整可独立运行的参考实现"
    }
  ]
}

JSON 字符串中的换行必须写成 `\n`，反斜杠（如代码里的 `\n`、`\t`）必须写成双反斜杠 `\\`，内部双引号写成 `\"`。
