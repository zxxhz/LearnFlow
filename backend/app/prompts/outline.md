## 编排原则
1. **先识别学科属性，按学科规律组织脉络**：
   - **编程开发类**：从能跑通的最小例子切入，「核心语法/机制 → 典型工程场景 → 底层原理与常见坑」交替推进，确保每章都有可动手的实操切入点；
   - **数理逻辑类**（高数、线代、概率、物理等）：严格按前置依赖拓扑排序（如极限 → 导数 → 微分中值定理 → 积分），兼顾几何直观/物理图景、核心定理推导与典型题型计算；
   - **理论与通识类**：按「具体问题/真实场景 → 核心概念与机制 → 体系框架与对比 → 综合案例分析」推进。
2. **对齐学习者起点**：
   - 零基础/初学者：第 1 章必须铺垫必要的直觉与基本概念，禁止直接抛高阶术语；
   - 有基础/进阶者：跳过常识性铺垫，直接切入核心机制、复杂边界与易混点辨析；
   - 若学习者画像中存在历史薄弱点或常见误区，在对应章节的要点中专门安排针对性辨析。
3. **严格的依赖自检**：后一章用到的概念、语法或公式，必须在前面的章节中已经讲过；章与章之间跨度均匀，避免某一章信息过载而下一章内容空洞。
4. **范围优先**：若「范围与期望」中指定了特定考纲、项目目标或教材体系，严格以该范围为准。

## 命名与颗粒度规范
1. **课程标题（title）**：8-16 字，像一本口碑扎实的专业教材名（如「C++ 现代内存管理与实战」「高等数学核心概念与直观精讲」）；**禁止使用冒号副标题**，禁用「从入门到精通」「零基础速成」「完全指南」等营销套话。
2. **章节标题（chapter title）**：4-14 字，简短具体、直指本章核心对象（如「指针运算与内存布局」「导数定义与切线几何意义」）；**禁止出现冒号**，不加「第一章」「第1节」「基础篇」等编号或前缀。
3. **章节要点（points）**：每章 3-5 个要点。
   - 每个要点必须写成「具体动作 + 核心概念/机制/场景」（如「利用快慢指针判定链表成环」「推导复合函数求导的链式法则并处理多层嵌套」）；
   - **禁止写成「标签：说明」的冒号格式**；
   - **禁止写空泛口号**（如「了解相关背景」「掌握基本用法」「进行综合实战」），要点将直接作为后续撰写讲义的小节提纲，必须具体到一眼看出这节要讲什么。
4. **词汇黑名单（绝对禁用）**：底层逻辑、闭环、赋能、抓手、链路、赛道、跃迁、蜕变、升华、颠覆、降维打击、弯道超车、认知升级、高维视角、生态位、护城河、价值感、仪式感、松弛感、复盘、沉淀、刻意练习、成长型思维、极致、优雅、毋庸置疑。
